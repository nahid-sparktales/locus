# Locus 1.2.0 — Full UI & Feature Audit (2026-07-26)

A multi-agent audit swept every interactive control, the WebSocket/REST state
machine, concurrency and lifecycle, keyboard handling, the app↔backend
contract, and the Model Library. Six independent reviewers produced 52
findings; each major finding was adversarially verified against the code
before being accepted (22 confirmed, 1 refuted, 27 additional minors).
Everything listed below as fixed shipped in 1.2.0, with regression tests where
the behavior is testable off-backend.

## Confirmed and fixed — state machine & reliability

| Finding | Resolution |
| --- | --- |
| `turn_done` without `message_end` (or a backend `error`) left the assistant bubble streaming forever and busy state stuck | All streaming blocks are finalized on `turn_done`, `error`, and disconnect; covered by unit tests |
| A dropped connection left unanswerable permission cards, stuck busy state, and latched `pending*` flags with no recovery path | `recoverFromLostConnection()` resolves awaiting/running tool cards, clears busy and every pending flag |
| Clear Chat could latch shut forever if the backend accepted the reset but the acknowledgement was lost | 10-second watchdog releases the latch and tells the user |
| Restoring a checkpoint from a different workspace immediately wiped the restored transcript (set_cwd ack treated as a user workspace switch) | Restore pre-acknowledges the checkpoint's workspace |
| `resume()` kept the previous session's plan, transcript context, and could have its transcript wiped by a late `session_info` | Resume clears stale state and pre-acknowledges the session's cwd |
| Tokens arriving without `message_start` were silently discarded | A streaming block is synthesized on the first orphan token |
| `permission_request` for an unknown tool id was dropped — backend waits forever | A standalone permission card is created |
| `stop()` left `pendingRetry` set, misrouting the next session acknowledgement | Cleared in `stop()` |
| `BackendService` mutable state was touched from three threads without synchronization | The class is now `@MainActor`; URLSession callbacks hop to the main actor |
| The bundled Python agent's stdout/stderr pipe was never drained — a chatty backend deadlocks at 64 KB | Pipe drained continuously into a capped diagnostic buffer |
| Backend shutdown hung off a window's `onReceive` — quitting with the window closed orphaned the Python child | Termination observer lives on the model |

## Confirmed and fixed — input & controls

| Finding | Resolution |
| --- | --- |
| Composer arrow keys were always swallowed: no caret movement in multi-line drafts, and ↑ destroyed an unsent draft irrecoverably | History recall only on an empty composer (or while browsing); the unsent draft is stashed and restored; the cursor resets when a recalled entry is edited |
| Command palette advertised "↑↓ Navigate ↵ Select ⌘K Close" — none was implemented | All three implemented, plus Esc |
| `requestPlan` flipped mode while busy and overwrote the user's draft with a canned prompt when disconnected | Guarded, and the canned prompt no longer routes through draft preservation; plan buttons disable while busy |
| Send button looked enabled during a pending permission but `send()` silently no-oped | Send disables with an explanatory tooltip; sending while busy queues instead of dropping |
| `⌘⇧K` was registered twice (menu bar + workspace menu) | Single registration |
| "Export Current Session…" could silently no-op; empty preview URL opened a blank browser tab | Export falls back with a toast and the menu disable condition matches reality; preview URLs require a host |
| Rail "Sessions" button was a decorative no-op | It now collapses/expands the sessions sidebar |
| Session previews showed the internal `[Locus mode: …]` prompt wrapper | Stripped for display |
| SwiftUI `Menu` controls (model picker, workspace menu, actions menu) are not exposed as accessibility *buttons* on current macOS, breaking the shipped UI tests | UI tests match menu anchors by identifier on any element type; suite verified green on macOS 26 |
| UI-test mode still called the live backend: with a real agent running on port 8791 (as on any machine where Locus is in daily use), `refreshMetadata` replaced the seeded test fixtures with real session data mid-test | UI-test mode never touches the network; seeds use a fixed `/tmp` workspace; tests launch with `-ApplePersistenceIgnoreState` so stale window-restoration state can't suppress the main window |
| The archived-sessions toggle exposed one wide accessibility element spanning label + switch, so synthesized (and assistive) clicks on its center hit dead space | The switch is its own accessibility element; label sits beside it |

## Confirmed and fixed — Model Library

| Finding | Resolution |
| --- | --- |
| Cancelling a download showed a red "cancelled" error and frozen progress (`URLError(.cancelled)` ≠ `CancellationError`) | Both cancellation shapes are treated as cancel; cancel takes effect immediately |
| Overlapping searches / rapid model switches (A→B→A) could clobber the live request's results, spinner, or error state | Generation counters guard every async completion |
| Download task survived sheet dismissal uncancellably and duplicate pulls were possible | Downloads cancel on dismiss; duplicate starts are guarded |
| Sharded GGUF repos showed one shard's size as the model size | Sizes sum across shards per quantization |
| A dead connection mid-pull showed frozen progress for 24 h | 5-minute idle timeout (resource limit still 24 h) |
| Non-2xx from Ollama discarded the actionable error body; per-pull URLSessions leaked | Ollama's own message is surfaced; sessions are invalidated |
| `openRepositoryFromQuery` permanently inserted fabricated result rows | Selection no longer fabricates list rows |
| `loadInitial` search wasn't tracked and could overwrite a user search | Tracked in the same task slot |

## Also hardened (from the minor list)

- `refreshContextFiles` merges by id — files removed mid-refresh stay removed.
- `activateInstalledModel` prefers exact/owner-qualified matches and only uses
  the bare repo name when it is unambiguous.
- `HealthResponse` and `AppSettings` decode tolerantly, so a missing optional
  field can't brick the connection or silently reset saved settings.
- Change-tool detection is defined once and shared.
- Pinned sessions sort first; sessions order deterministically by recency.

## Refuted during verification

- "pendingCheckpointRestore survives a dead backend and hijacks the next
  session_started" — the verifier showed the flag is cleared on the error
  path in question; the related real gaps (disconnect, watchdog) are fixed as
  above.

## Explicitly out of scope (requires the Python backend repo, absent on this machine)

- True `/compact` support, permission *modes* (auto-accept / bypass), MCP
  servers, subagents, and hooks — these need `ollama-code-cli` changes; the
  GUI passes unknown slash commands through and already renders `slash_result`.
- Live end-to-end verification against a running agent (REST/WS behavior was
  audited for internal consistency instead).
