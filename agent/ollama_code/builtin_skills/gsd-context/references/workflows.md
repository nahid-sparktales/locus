# Context operations

## Map

Produce concise maps for stack, entry points, architecture, data, integrations, testing, and operational boundaries. Include paths and the reason each area matters.

## Graph

Use a dependency or flow diagram only when it clarifies three or more relationships. Keep nodes at one useful abstraction level and annotate uncertain edges.

## Documentation

Update existing canonical docs when available. Avoid duplicating facts already clear from code unless the relationship is non-obvious.

## Learnings

Capture verified conventions, traps, and decisions with evidence and scope. Revisit stale learnings when dependencies or architecture change.
