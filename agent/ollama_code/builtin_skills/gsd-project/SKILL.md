# GSD Project for Locus

Adapted from Get Shit Done by Lex Christopherson under the MIT License.

Use `.planning/` as human-readable project state. Do not overwrite an existing planning system without reading it and preserving compatible content.

1. Establish the project's outcome, users, constraints, non-goals, and definition of done.
2. Map existing code before proposing a roadmap for a non-empty repository.
3. Create milestones with observable outcomes, ordered phases, dependencies, risks, and acceptance criteria.
4. Audit roadmap coverage against the project outcome and current workspace; repair gaps explicitly.
5. Complete a milestone only after its phases verify. Preserve a concise retrospective and unresolved follow-ups.

Read `references/workflows.md` for initialization, milestone, audit, and completion artifacts.

Pre-flight: ensure the roadmap describes outcomes rather than a speculative file inventory, and that every completed milestone has evidence.
